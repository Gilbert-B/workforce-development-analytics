# Workforce Development & Performance Intelligence

A multi-cohort workforce analytics case study for a **fictional digital payments company** that trains Payments Operations Associates in recurring cohorts. The project goes from synthetic operational data, through Python and SQL, to a Power BI semantic model and report.

> **All data in this repository is synthetic.** People, cohorts, scores and dates are generated by code in this repository. Nothing comes from any real organisation.

**Status:** 🟡 **Build 01 of several** (multi-cohort training foundation) is complete. The Power BI report is in development.

---

## The business problem

The fictional company runs recurring 8-week onboarding cohorts. Leaders need to know:
- how many trainees started and are still active on any given date;
- whether attendance is healthy, and where it's simply unrecorded;
- whether core competencies are improving, comparing cohorts **week for week** rather than by calendar date.

Later builds extend this to certification, readiness, deployment and the first 90 days of operational performance.

## Relationship to my original project

This builds on a Power BI learner-performance dashboard I created professionally. That dashboard was designed for a **single cohort**, using Azure SQL, Power Query and an Import-mode model.

This Portfolio Edition is a **new, fictional scenario**. Its multi-cohort design, Python pipeline, banking and fintech domain, and everything in this repository were built for the rebuild. They were not part of the original project, and no original files or data are used here.

## Data model (reporting layer)

| Table | One row per |
|---|---|
| `dim_cohort` | training cohort, with schedule status as of the snapshot date |
| `dim_enrolment` | employee in a cohort (a person can enrol more than once) |
| `dim_competency`, `dim_programme_week`, `dim_date` | competency / programme week / calendar day |
| `fact_attendance` | eligible enrolment × scheduled session (Present / Absent / Unrecorded) |
| `fact_assessment` | enrolment × competency × programme week (score 0–100) |
| `fact_enrolment_status_event` | dated lifecycle event (enrolled, cancelled, started, withdrawn, completed) |

Full details are in [`docs/data_dictionary.md`](docs/data_dictionary.md).

## How to run it

**You need:**
- Python **3.11+**;
- SQL Server **2017+** (the free Express or Developer edition);
- Microsoft **ODBC Driver 17 or 18 for SQL Server**, which is usually installed with SQL Server or SSMS.

The SQL steps are optional: the CSVs are already committed, and the generator tests need no database.

```powershell
# 1. Get the code and install the two dependencies (pyodbc, pytest)
git clone https://github.com/Gilbert-B/workforce-development-analytics.git
cd workforce-development-analytics
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 2. (Optional) regenerate the synthetic data — produces identical files
python python/generate_synthetic_data.py
#    other scenarios:  --seed 42   --as-of-date 2026-10-01

# 3. Build and load the database (creates WorkforceDevAnalytics), then validate
python python/load_to_sql.py --server "localhost\SQLEXPRESS"
#    default SQL Server instance:  --server localhost
#    SQL login instead of Windows login: set WDA_SQL_USER / WDA_SQL_PASSWORD

# 4. Run the tests
python -m pytest                                   # generator tests
$env:WDA_SQL_SERVER = "localhost\SQLEXPRESS"
python -m pytest tests/test_sql_integration.py     # database tests
```

On macOS or Linux, use `python3 -m venv .venv` and `source .venv/bin/activate`.

**Connect Power BI:** Get Data → SQL Server → server `localhost\SQLEXPRESS`, database `WorkforceDevAnalytics`, **Import** mode. Then select the `rpt.*` views.

## Privacy

- Every record is generated; names are random combinations from fictional name lists.
- No original Power BI files, queries, connection details or organisational information are in this repository or its history.
- `.gitignore` blocks Power BI files, caches, `.env` files, database backups and private working documents by default.
- Database credentials are never stored in the repository. The loader uses Windows authentication, or environment variables (see `.env.example`).
