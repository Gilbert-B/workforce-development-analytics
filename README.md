# Workforce Intelligence Suite

**From the training academy to the operations floor: three Power BI reports on one shared semantic model, fed by a MongoDB → Python → SQL Server pipeline.**

A portfolio case study for a **fictional digital payments company**. It trains Payments Operations Associates in 8-week cohorts, approves them for readiness and deploys them into a payment-exceptions team. The suite answers one connected question: *does our training produce people who perform, and how quickly?*

> **All data in this repository is synthetic.** People, cohorts, cases, scores and dates are generated by code in this repository. Nothing comes from any real organisation.

**Status:** all three reports and the full pipeline are built and tested in a development environment (171 tests). The owner's Windows / Power BI Desktop validation is in progress: see [`docs/validation_checkpoints.md`](docs/validation_checkpoints.md) and [`docs/progress.md`](docs/progress.md).

## The three reports

| | Report | Question it answers | Look |
|---|---|---|---|
| 01 | **Workforce Development & Readiness** | Who is in training, how are they progressing, who needs coaching, who is certified and approved? | Dark "designed canvas", bookmarks, Trainee 360 drill-through |
| 02 | **Payment Operations Performance** | How is the exceptions team doing on SLA, quality and backlog, and how fast do new graduates ramp up? | Light command centre, tenured benchmark, Agent 360 drill-through |
| 03 | **Workforce Outcomes & Training Effectiveness** | How do graduates do in their first 30 / 60 / 90 days, and does training performance predict it? | Light, insight-led, Graduate journey drill-through |

All three `.pbip` files point at **one** semantic model (`definition.pbir` → `byPath`), so a measure such as *SLA Met %* has a single definition everywhere. Screenshots are in [`docs/screenshots/`](docs/screenshots/), and the story is in [`docs/case_study.md`](docs/case_study.md).

### Headline findings (synthetic data, as at 30 Jun 2027)
- **Ramp-up:** graduates meet SLA on **75%** of cases in their first 30 days, against **84%** for tenured agents. The gap closes to about 1 point after 90 days.
- **Proficiency:** **74%** of graduates retained to day 90 reach the proficiency standard by then, on average after **64 days**.
- **Training predicts, moderately:** **24%** of the top third by training competency are proficient within 30 days, against **8%** of the bottom third. By day 90 most of the bottom third have caught up.
- **Retention:** trainees who were on the coaching watch list kept **90.5%** to day 90, against **96.6%** for the rest.

## Architecture

```
config/*.toml  (every synthetic assumption, commented)
      │
      ▼
python/generate_*.py ──► training data: CSV (Builds 01-02)           ┐
                     ──► agents, deployments: CSV (Build 03)          │ reproducible
                     ──► payment cases: JSON documents (Build 03)     ┘ (seeded)
                                  │
                                  ▼
                      MongoDB  wda_ops.payment_cases   (nested events, QA, rework)
                                  │  python/etl/mongo_to_sql.py
                                  │  incremental (updated_at, _id) checkpoint,
                                  │  idempotent, rejects bad documents with a reason
                                  ▼
SQL Server  WorkforceDevAnalytics
   core.*   tables with keys and constraints
   stg.* / etl.*   staging, rejected records, load runs
   rpt.*   reporting views: training, operations, 30/60/90-day outcomes (Build 04)
   validation: 26 + 49 + 26 + 14 checks, plus MongoDB ↔ SQL reconciliation
                                  │  Import
                                  ▼
Power BI: ONE semantic model (TMDL, 22 tables, 26 relationships, 86 measures)
   ├─ Report 01  workforcedevelopmentanalytics.pbip
   ├─ Report 02  payment-operations.pbip
   └─ Report 03  workforce-outcomes.pbip
```

**One command builds the whole database:** `python python/build_all.py --server localhost` (about 1 minute).

## What it demonstrates

| Skill | Where |
|---|---|
| Realistic, reproducible synthetic data: learning curves, individual variation, exits, deliberate data-quality faults | `python/generate_*.py`, `config/` |
| Document store → relational ETL: incremental checkpoint with tied timestamps, crash-resume, whole-document replacement, rejection logging, reconciliation | `python/etl/` |
| Relational design, effective-dated status, honest handling of unknowns (unrecorded ≠ absent, open ≠ missed, not reached ≠ zero) | `sql/001`, `sql/004`, `sql/008`, `sql/011` |
| Analytical SQL: window functions, honest 30/60/90-day windows, tenured benchmarks | `sql/009`, `sql/011` |
| A shared semantic model built from code: TMDL generated from the SQL contract, additive-only check against the validated baseline | `powerbi/tools/build_model.py`, `check_model_additive.py` |
| DAX: status-safe denominators (`KEEPFILTERS`), blank-not-zero ratios, benchmark measures with `REMOVEFILTERS`, drill-through labels | model `tables/*.tmdl` |
| Report design as code: PBIR pages, themes, navigation, drill-through, schema- and model-checked | `powerbi/tools/` |
| Automated validation: 171 pytest tests and SQL check suites | `tests/`, `sql/*validation*.sql` |

## Run it

**Prerequisites:**
- Python 3.11+;
- SQL Server 2017+ (Developer or Express) with ODBC Driver 17/18;
- MongoDB (Docker `mongo:7.0` or Community Server);
- Power BI Desktop.

```powershell
git clone https://github.com/Gilbert-B/workforce-development-analytics.git
cd workforce-development-analytics
pip install -r requirements.txt
python python\generate_build03_data.py          # payment-case documents (not committed)
python python\build_all.py --server localhost   # Builds 01-04 + MongoDB + ETL + all checks
python -m pytest                                 # set $env:WDA_SQL_SERVER for the database tests
```
Then open any `powerbi\*.pbip` in Power BI Desktop and click **Refresh**. Expected numbers for every step and every report: [`docs/validation_checkpoints.md`](docs/validation_checkpoints.md).

**Other routes:**
- **The original 2 Nov 2026 snapshot** (Report 01's first validated numbers): `python python\full_reset.py --server localhost --confirm --dataset baseline`.
- **SSMS only, no Python:** see [`docs/walkthrough.md`](docs/walkthrough.md) (Build 01).

## Relationship to my original project

This builds on a Power BI learner-performance dashboard I created professionally. That dashboard was designed for a **single cohort**, using Azure SQL, Power Query and an Import-mode model.

This Portfolio Edition is a **new, fictional scenario**. Its multi-cohort design, Python pipeline, banking and fintech domain, and everything in this repository were built for the rebuild. They were not part of the original project, and no original files or data are used here.

## Privacy
- Every record is generated; names are random combinations from fictional name lists.
- No original Power BI files, queries, connection details or organisational information are in this repository or its history.
- Credentials are never stored in the repository. The loaders use Windows authentication, or environment variables (see `.env.example`).
